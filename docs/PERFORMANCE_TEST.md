# Automated performance test

Open **Settings → Performance Test**, choose a level, then **Prepare selected level (reload)**. On the fresh page tap **Start … full-level test**. The tap unlocks audio on phones. Start with Frost 1, then compare Speed 1 and Gravity 2. Download each report before preparing another level. Each preparation reloads the page. **Run all 27 levels** covers every campaign stage, with a fresh page between stages. Desktop continues automatically; touch devices show a Start button after each reload to unlock audio. The suite saves timing reports in this tab’s session storage after each level, then exports one combined JSON report. Keep the same tab open. Stop, backgrounding, errors and timeouts pause the suite; **Continue suite (reload)** retries that stage and retains the partial attempt. Storage failures halt progression rather than discard results. Boss fights are not included. A reload clears page-owned resources but does not guarantee cold browser/disk caches or immediate GPU-process memory reclamation.

The bot plays to the finish with a disposable save, Lorenzo, a repeatable seed and invulnerability. It is reactive rather than a recording of human inputs. Reports split the whole run into 30-simulation-second windows, retaining the final partial window. The first two simulation seconds and run-in are excluded; synchronous entry cost is recorded separately. A simulation watchdog (stage duration plus 45 seconds) and wall-clock watchdog (at least three minutes, or three times that simulation limit) stop stuck runs. A timeout is not a successful complete-level sample.

Keep the app visible and in the same orientation. Backgrounding or rotating stops with an interrupted report. Stop test is always available. Resolution stays at the starting density; the previous density/pin policy is restored afterwards. Quality does not automatically fall during the test, so a struggling device may run slowly. This is protocol `bot-full-level-isolated-v3`; older adaptive v1 and sequential v2 results are not directly comparable.

The test disables the installed dev toolkit and suspends breadcrumb persistence/uploads. Renderer-settle saving/telemetry is suppressed. Menu warmers skip gameplay. Video recording must be stopped first. Current music settings are retained. There is no per-frame network/storage work. Normal play does not enable profiling clocks. Thirty-second boundaries summarize bounded samples in memory; that small boundary cost can affect the following frame and is not ordinary gameplay work.

Afterwards use **Share / download report** or **Copy report**. iPhone uses file sharing where supported; desktop downloads JSON. The latest single or combined report is saved locally after playback stops; suite progress also lives in session storage across reloads. Previous report reopens it. Nothing is sent automatically.

Reports contain build/browser/viewport/settings, stage/seed/status, frame intervals and percentiles, worst frames with position, simulation/bot/audio/draw/blit/dev/diagnostic timings, resolution, prop-cache statistics, audio health and JS heap when available. Each window also separates CPU time spent submitting background, overlay and glow textures to WebGL. These upload timings include any synchronous browser/driver wait; they are not GPU execution measurements. Upload totals and renderer totals include the first presented frame whereas interval samples start on the second frame.

Update includes bot time; blit includes overlay painting and submission. Do not sum overlapping categories. Frame gaps do not establish causality. GPU, compositor and garbage collection are not directly timed. Prop-cache bytes and JS heap do not measure total browser memory. Chrome tab-hover memory can include native/GPU resources; iPhone generally exposes no JS heap metric. This test has no reliable total-memory safety threshold.

Validation artifacts and local browser checks live in `work/mockups/performance-test/`. Headless Chrome results verify functionality and give investigative clues, not desktop or physical-iPhone performance acceptance. Historical short-suite artifacts use older protocols.

Local v3 validation: a full Frost 1 run at 1732×1050 / DPR 2 completed through 84 simulation seconds, with three windows near 60 FPS and WebGL submission averaging approximately 0.15–0.16 ms per render. This did not reproduce the submitted v1 report's persistent 40 ms Frost submission cost. The full run predates the additional startup-warmer suppression; the portrait segmentation/share/interruption check and subsequent Speed reload/cancellation used the updated build. No claim of a memory-leak fix follows from these checks.

Suite validation: unit checks cover all 27 campaign IDs, serialized progress, interrupted attempts, retries and final completion. The browser smoke shortens the suite and run durations solely to check reload/gesture/export behavior; it does not claim all 27 full levels were device-tested.

Recovery: navigation replaces the current history entry rather than adding one per level. The handoff explicitly says results were saved and the next test is loading. If the browser closes/crashes, reopen Settings → Performance Test → Resume saved suite to restore the last combined report from local storage; a partially measured level lost in a browser-process crash must be rerun. These safeguards do not diagnose or prove a fix for browser-process crashes.

Benchmark navigation now requests a lightweight gate-only handoff. The new document waits two seconds, while visible, before loading fonts, creating game canvases or requesting the game script. This separates unloading the previous game from booting the next one; it does not force browser memory reclamation or establish the crash cause. The latest handoff phases (leaving game, lightweight page, loading game, game ready) are saved separately and included on export. There are no per-frame writes. Normal game startup does not take this detour.

Script-load failures during a benchmark retry at most twice (three requests total), using the same bundle URL. Failed request details (time, URL, stage, attempt and browser online flag) are stored and included as `lastGameLoadError` on export. The online flag does not establish server reachability. A script-element error does not provide an HTTP status or prove memory exhaustion. The latest error can predate the exported run; compare its timestamp. Local browser fault injection verifies a transient failure recovers and persistent failure stops after three attempts.
